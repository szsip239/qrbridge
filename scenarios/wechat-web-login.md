# 虚拟摄像头扫码：微信网页登录

## 目标

把电脑上的二维码图片作为摄像头画面送进安卓手机里的原版微信，由 Agent 在同一块屏幕上操作“扫一扫”并点确认登录，最后以网页端已登录为准。不涉及付款。

实现路线：以 ADB shell 身份在手机上运行一个常驻主机程序，用系统的 VirtualDeviceManager 创建虚拟设备、虚拟屏幕和虚拟摄像头；App 开在虚拟屏幕上，取景画面来自电脑送入的图片。不依赖 AndroMeld，不 root，不改包。研究依据为统一调研看板课题 `desktop-mobile-qr-bridge` 的“公开实践更新”（2026-11-15）。原型代码在仓库根目录。

## 前置条件

- vivo V2309A，Android 16，已开启 USB 调试并认可本机。
- 手机上的微信已登录。
- 电脑浏览器打开一个用户本人可控的微信网页登录码。
- 实际使用时没有 USB：主机程序与连接方式分开，启动和通信也要能走无线调试。重启手机后需要重新启动主机程序。

## 验收关卡

按顺序执行，任何一关不过就停下报告，不改走相册识别或 AndroMeld。

| 关卡 | 通过标准 | 执行 |
| --- | --- | --- |
| 1 创建 | 虚拟设备和虚拟摄像头出现在 `dumpsys virtualdevice` 与相机服务中 | Sol xhigh |
| 2 画面到达 App | 虚拟屏幕上的测试相机 App 取到送入的已知二维码并解出原文 | Sol xhigh |
| 3 同屏操作 | 在同一块虚拟屏幕上能截图、读控件树、点击，并看到界面变化 | Sol xhigh |
| 4 无线传输 | 不经 USB 传输完成关卡 1–3；启动它的连接断开后主机程序仍在 | Sol xhigh |
| 4b 无 USB 启动 | 全程不接 USB：原生无线调试配对、启动主机程序并完成关卡 1–3；拔线或 adbd 重启后主机程序仍在；重启手机或换 Wi-Fi 后能重新启动 | Sol xhigh，需用户在手机上配合 |
| 5 微信取景 | 微信“扫一扫”取景框显示送入的图片 | Terra high fast |
| 6 业务结果 | 微信识别登录码、点确认登录后，网页端显示已登录 | Terra high fast |

“识别到码”“进入确认页”“网页端已登录”分开记录。遇到人脸、密码、短信验证码或任何付款页面即停下报告。

## 执行记录

- 2026-11-15：关卡 1–4 通过，详见 [实测结果](../RESULTS.md)。关卡 4 是先经 USB 打开 ADB 的 TCP 监听、再全程走 Wi-Fi，USB 线仍插着供电；它不等于关卡 4b。
- 2026-11-15：关卡 5 未通过。微信主界面在虚拟屏幕，扫一扫两次均迁到物理屏幕并连接相机 0；包括一次授权的强制停止后冷启动。关卡 6 因关卡 5 未通过而未执行：识别登录码、进入确认页、网页端已登录均未验证。详见 [实测结果](../RESULTS.md)。
- 2026-11-15：isolated 修复后复测，微信取景显示已知码并解码，活动转储与监听显示扫码活动留在虚拟显示，相机服务显示连接虚拟相机；但控件树只有空节点，指定的控件树证据未取得。关卡 6 的识别登录码、进入确认页、网页端已登录三项均观察到，网页会话随后退出；详见 [实测结果](../RESULTS.md)。
- 2026-11-15：关卡 4b 三项通过：原生无线配对连接及关卡 1–3、物理拔线后同一主机继续解码与点击、重启后无 USB 重建主机并解码。重启后无线调试开关关闭，需用户正常解锁并重新打开；电脑配对保留，无需再配对，连接端口改变。初次设置与读配对界面按用户要求通过 USB ADB 完成，拔线与重启恢复阶段均无 USB；不代表初次配对前已拔线或全自动重启恢复，换 Wi-Fi 未测。实验资源已清理；按用户选择保留无 USB 的原生无线连接和电脑配对，传统 TCP 关闭、转发为空。详见 [实测结果的关卡 4b](../RESULTS.md#关卡-4b原生无线调试物理拔线与重启重连round7)。
