# 0.2.0 手机验收计划

构建 worker 未操作手机。由获授权的独立手机 worker 执行；实际地址、设备资料、日志和截图只存 `.local/accept/wake/`。遇到人脸、密码、短信验证码、付款或风险提示立即停下报告；不 root、不改其他系统或安全设置。重启、恢复无监听、开关和权限变更均按协调者授权范围执行。

round14 是 0.1.0 基线，不能替代 0.2.0 新行为验收。

## 准备

1. 记录原版本、已配对设备、`WRITE_SECURE_SETTINGS`、通知权限、无线调试、Wi-Fi、USB 调试、`service.adb.tcp.port`、`persist.adb.tcp.port`、现有 5555 监听以及 Tailscale 状态。
2. 覆盖安装 `.local/artifacts/qrbridge-wake-0.2.0.apk`，核对版本 0.2.0／versionCode 2／包名 `dev.qrbridge.wake`。保留数据和原签名，确认旧配对和 grant 仍在。
3. 首次打开升级版，用户允许结果通知。vivo 用户在应用管理中允许「自启动」，记录实际入口；不要替用户改其他设置。自动恢复依赖这些前置条件。
4. 需“无 5555 监听”的用例，先在获批 USB 通道用 `adb usb` 等已有恢复方式建立基线并核实监听已消失，避免把旧监听误判为本次成功。

## 新增／回归用例

| 用例 | 步骤 | 预期与证据 |
| --- | --- | --- |
| 已有监听、无 Wi-Fi | 保持 5555 已运行，关闭 Wi-Fi，再点按钮。可同时保持无线调试关闭。 | 立即显示「5555 已在运行」；不显示 Wi-Fi 要求、不打开设置、不改 `adb_wifi_enabled`。保存操作前后设置和监听证据。 |
| 已有监听、无 grant | 在获批范围撤销 grant，保持监听存在、无线调试关闭，再点按钮。 | 同样显示「5555 已在运行」，不要求 grant 或手动开无线调试。之后按基线恢复权限。 |
| 新开端口并恢复开关 | 无监听、已配对、有 grant、有 Wi-Fi，原无线调试关闭，点按钮。 | 显示「成功」；5555 接受连接；无线调试恢复为 0，且 5555 仍在。持久 TCP 属性不变。 |
| 保留已开的无线调试 | 无监听，原无线调试开启，点按钮。 | 成功后仍开启，不额外关闭用户原有开关。 |
| 无监听、无 Wi-Fi | 有 grant 和无 grant 各执行一次。 | 提示「请先连接任意 Wi-Fi（包括别人的热点）」；不开设置、不写无线调试开关。 |
| 无 grant 手动路径 | 无监听、无线调试关闭、有 Wi-Fi，未授予 grant，点按钮。 | 提示「请打开无线调试，再点开启」，跳到系统设置；用户开启后返回再点可成功。 |
| 新网络许可超时后第二次点击 | 无监听、有 grant、原无线调试关闭，换一个未允许调试的 Wi-Fi。点击，先不接受系统网络许可，等约 15 秒。随后用户允许，再点。 | 首次显示「等待超时。请允许此网络调试，再点开启」，忙状态解除；第二次可继续并成功，应用无需重启。首次临时开关需恢复。 |
| 开机时已有 Wi-Fi | 已配对、有 grant、有通知权限，vivo 自启动已允许。重启后解锁并保持／连接一个已信任 Wi-Fi，**不打开应用、不点按钮**。 | 系统启动 JobService，一次恢复 5555，发一条「成功」通知。原无线调试关闭时用完关回去；5555 保持。记录 `dumpsys jobscheduler`、通知、设置与监听。不能以强制运行 job 代替自然开机验收。 |
| 开机后晚些连接 Wi-Fi | 重启解锁后先只用移动网络，不打开应用；稍后连接任意 Wi-Fi或另一部手机的热点。 | 连接前只有待执行任务，无无线调试开关写入；Wi-Fi 出现后执行一次并发结果通知。不要要求与 Mac 同网，也不要求网络已通过外网验证。 |
| 本次开机不再重复 | 自动成功后切换 Wi-Fi／开关 Wi-Fi数次；如获批，再清除监听，观察本次开机。 | 已完成任务不再自动运行，不重复通知；只有手动按钮或下次重启重新触发。 |
| 自动失败通知 | 重启后接入未允许调试的新网络，先不接受许可，让自动任务超时。 | 一条简短超时原因通知；临时开关恢复；本次开机不循环重试。用户接受网络许可后可手动再点成功。 |
| 自动任务中 Wi-Fi 丢失 | 在自动连接等待期间关闭／断开 Wi-Fi。 | 任务结束并发一条原因通知，不自动重试。若本任务打开过无线调试，清理后恢复关闭。记录调度器是否发出 stop，以及开关清理情况。 |
| 手动成功结束待执行任务 | 重启后开机任务仍在等待或尚未执行时，用户手动点按钮成功。 | 开机待执行任务取消，本次开机不继续监听 Wi-Fi；不重复开启端口。若任务已经启动，最终不留下临时无线调试开关。 |
| 通知拒绝 | 用户拒绝应用通知，再执行一次重启恢复。 | 端口恢复仍执行，系统不显示应用通知；不会反复弹权限申请或替用户开启通知。用户可从系统设置重新允许。 |
| 蜂窝网络经 Tailscale | 5555 自动或手动开启后，关闭 Wi-Fi、拔 USB，让 Tailscale 在移动网络在线；Mac `adb connect "$PHONE_TAILNET:5555"` 后执行 `shell id`。 | Mac transport 为 device，返回 shell 身份；证据确认 Wi-Fi／USB均断开。应用自动恢复端口和 Tailscale自身开机连接分别判定。 |

## 配对与界面回归

- 覆盖升级不重新配对。全新安装时，分屏保持系统配对码窗口打开，输入配对端口和六位码，显示「配对成功」后点开启。
- 若用户授权，测试错码恢复和系统撤销配对；应有失败提示，菜单可重新配对。库无配对读取超时的旧风险继续记录。
- 调整分屏／旋转，操作结果应可读；按钮操作时禁用。开机后台运行与手动操作重叠时，不应互相覆盖无线调试原状态或重复恢复端口。

## 报告与收尾

分别报告覆盖升级、端口优先检查、自然开机调度、开关恢复、单次通知和蜂窝连接的通过／失败／未执行。记录自然开机到任务实际开始的时间，区分 vivo 未允许自启动、通知被拒绝、系统调度延迟、网络许可未接受和协议失败。只读 `dumpsys jobscheduler` 可辅助证明，强制触发 job 仅能算隔离诊断，不算开机自动通过。

按协调者要求保留监听、grant、配对和自启动，或恢复测试前基线；不自行关闭用户当前远程入口。原始设备资料和配对信息不进公开仓库。
